# Agentic Studio - Platform User Guide

Welcome to **Agentic Studio**, an autonomous freelance software development agency powered by the **Agent Development Kit (ADK)** and an **Agent-to-Agent (A2A)** typed communication protocol.

This platform automates the end-to-end Software Development Life Cycle (SDLC), transforming high-level client software ideas into fully tested, security-reviewed, and packaged software products.

## 1. Prerequisites & Environment

* **Operating System**: Windows, macOS, or Linux.
* **Python**: Python 3.13+ (tested and verified on **Python 3.13.15**).
* **Virtual Environment**: `.venv` in the repository root.

```bash
# Verify Python version
.venv\Scripts\python --version
# Expected: Python 3.13.x
```

---

## 2. Quickstart Guide

### Step 1: Activate Virtual Environment
```powershell
# Windows PowerShell
.venv\Scripts\activate
```

### Step 2: Run a Sample Client Request
You can immediately trigger the agency with a sample software prompt using mock mode:
```powershell
.venv\Scripts\python -m agentic_studio.cli --prompt "Build a production-ready URL Shortener REST service with SQLite and analytics" --workspace "./target_project" --mock
```

You will see live, color-coded A2A message exchanges streaming in your terminal as the agents collaborate to scope, design, implement, test, and package your application.

## 3. CLI Reference & Options

The command-line interface is accessed via `agentic_studio.cli`:

```text
usage: python -m agentic_studio.cli [-h] [--prompt PROMPT] [--workspace WORKSPACE] [--mock]

Agentic Studio Multi-Agent Agency

options:
  -h, --help            Show help message and exit
  --prompt PROMPT       Client software requirement prompt (Default: "Build a production-ready URL Shortener...")
  --workspace WORKSPACE Target directory to build the software in (Default: "./target_project")
  --mock                Force deterministic offline mock provider (no API key required)
```

### Examples:
```powershell
# Build a key-value store with TTL caching
.venv\Scripts\python -m agentic_studio.cli --prompt "Build a key-value store with TTL caching" --workspace "./cache_service" --mock

# Build a Markdown parser utility into a custom folder
.venv\Scripts\python -m agentic_studio.cli --prompt "Build a markdown to HTML converter CLI tool" --workspace "./md_converter" --mock
```

## 4. Execution Modes (Offline Mock vs Live Gemini)

The platform supports two runtime modes:

### Mode A: Deterministic Offline Mock (Default when `--mock` is used or no API key is set)
* **Zero API Cost & 100% Offline**: Requires no external network calls or credentials.
* **Simulated Bug & Fix Loop**: The developer agent intentionally introduces an edge case bug on attempt #1, QA catches it, and the developer fixes it on attempt #2.
* **Ideal for**: CI/CD pipelines, rapid local testing, and development of new agents.

### Mode B: Live Google Gemini Integration
* **Powered by**: Google Gemini models (`gemini-2.5-flash` or `gemini-2.0-flash`) via the official `google-genai` SDK.
* **Setup**: Create a `.env` file in the root directory:
  ```env
  GEMINI_API_KEY=your_google_gemini_api_key
  GEMINI_MODEL=gemini-2.5-flash
  ```
* **Run**: Execute the CLI without the `--mock` flag:
  ```powershell
  .venv\Scripts\python -m agentic_studio.cli --prompt "Build a CLI file organizer with regex filtering" --workspace "./file_organizer"
  ```

## 5. Understanding the Output & Artifacts

When an agency run completes, the target workspace directory contains a clean, deliverable repository:

```text
<workspace_directory>/
├── Dockerfile              # Containerization for deployment
├── README.md               # Client handover guide & usage
├── docs/
│   └── architecture.json  # Architecture spec & API contracts generated by Architect
├── tests/
│   └── test_*.py          # Pytest suite generated by QA Engineer
└── <package_name>/
    ├── __init__.py
    └── service.py         # Production source code written and fixed by Developer
```

### Verifying the Target Project
You can navigate into the generated directory and run its automated test suite directly:
```powershell
cd target_project
..\.venv\Scripts\pytest -v
```

## 6. Running the Test Suite

The Agentic Studio platform includes a comprehensive test suite covering message routing, state machine transitions, path safety, and full workflow simulation:

```powershell
.venv\Scripts\pytest -v
```

**Test Coverage Highlights:**
* `tests/test_protocol.py`: Validates Pydantic message envelopes, bus routing, and dead-letter detection.
* `tests/test_blackboard.py`: Validates ticket dependency DAGs and workspace path traversal prevention (`../../`).
* `tests/test_orchestrator.py`: Runs a complete 11-step SDLC cycle end-to-end.

## 7. Extending the Platform

* **Add a New Agent**: Subclass `BaseAgent` in `agentic_studio/agents/` and register mailbox handlers on the `A2ABus`.
* **Add New Message Actions**: Extend `ActionType` in `agentic_studio/protocol/models.py` with typed Pydantic payloads.
* **Adjust Circuit Breakers**: Modify `max_review_retries` or `test_timeout_seconds` in `agentic_studio/config.py`.
